# PB-TASK-0005｜ドローモード時のFPSカメラを実装する

## タスクの目的

ドローモード中に一人称視点へ切り替え、カメラを振ってシャオンダマを狙えるようにします。カメラ回転がそのままなぞり入力になるため、その土台をカメラ側で用意するタスクです。

## 完成時にできるようになること

- ドローモードに入ると、視点が頭の位置まで寄って一人称になります。
- 画角が広がり、周囲のシャオンダマが見渡せます。
- 自分のキャラクターが画面に映らなくなります。
- カメラを振ると、画面中央のレティクルでシャオンダマを狙えます。
- ドローモードを抜けると元の三人称視点に戻ります。

## 実施内容

- ドローモードの開始・終了の通知を受け取る
- カメラ位置をキャラクターの頭の位置へ移し、右肩越しオフセットを無効化する
- FOVを水平100度相当（Unityの垂直FOVで約68度）へ広げる
- ドロー中はプレイヤーキャラクターのモデルを非表示にする
- ドロー中もLook（カメラ回転）入力を有効にする
- 画面中央にレティクルを表示する
- 視点の切り替えを短時間の補間で行い、補間・入力処理に`Time.unscaledDeltaTime`を使う
- ゲーム状態のリセット時に、補間を待たず即座に通常の三人称視点へ戻す経路を用意する
- FOV値・補間時間・感度倍率をInspectorから調整できるようにする

## 対象範囲

- ドローモード中の視点切り替え（TPS⇔FPS）とその補間
- ドロー中のFOV変更・モデル非表示・レティクル表示
- ドロー中のカメラ回転入力の有効化

## 対象外

- なぞりの判定・シャオンダマの選択処理そのもの（ドローシステム側の担当）
- レティクルのビジュアルデザイン（仮の表示で構いません）
- スロー処理そのもの
- ドローモードの開始・終了・時間制限の処理

## 完了条件

- [ ] ドローモードに入ると一人称視点へ切り替わる
- [ ] 切り替えが瞬間的なカットではなく補間で行われる
- [ ] ドロー中は画角が広がっている
- [ ] ドロー中はキャラクターのモデルが表示されない
- [ ] ドロー中もカメラを回せる
- [ ] 画面中央にレティクルが表示される
- [ ] ドローモードを抜けると元の三人称視点・画角へ戻る
- [ ] スロー中でも視点の切り替わりとカメラの振り心地の速さが通常と変わらない
- [ ] Consoleに新しいエラーが発生しない
- [ ] 関連仕様と矛盾していない

## 確認手順

1. Unityで確認用シーンを開きます。
2. Play Modeを開始します。
3. ドローモードに入り、視点が一人称へ切り替わることを確認します。
4. 自分のキャラクターが表示されていないことを確認します。
5. カメラを振り、画面中央のレティクルで周囲のシャオンダマを狙えることを確認します。
6. 背後を向き、後ろのシャオンダマにもレティクルを合わせられることを確認します。
7. ドローモードを抜け、三人称視点と元の画角へ戻ることを確認します。
8. ダッシュでドローモードをキャンセルし、視点の復帰とFOVの変化が破綻しないことを確認します。
9. Consoleに新しいエラーが出ていないことを確認します。

## 前提・依存タスク

- PB-TASK-0003（TPSカメラの基本動作）が完了していること
- ドローシステム側で、ドローモードの開始・終了を外部から検知できる状態になっていること

## 実装時の注意点

- **ドロー中もカメラ回転（Look）入力を有効にしてください。** レティクル方式ではカメラを振ることがなぞり操作そのものになります。ドロー中にカメラ回転を止める実装にしないでください。
- シャオンダマの選択判定はドローシステム側の担当です。本タスクは視点の切り替えとレティクル表示までを範囲とします。
- ドロー中のカメラ感度に専用倍率を掛けるかどうかは未決です。倍率のパラメータだけ用意し、既定値は1倍にしておいてください。
- 補間・入力処理に`Time.deltaTime`を使わないでください。スロー中に5倍遅く見えます。
- 数値をハードコードしないでください。すべて`[SerializeField]`またはScriptableObjectでInspector調整可能にします。

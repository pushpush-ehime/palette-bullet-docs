# PB-TASK-0026｜想定画面一覧の確定

## タスクの目的

Palette BulletでPlayerが見る画面、HUD、Overlay、Menuを共通の画面IDで一覧化し、プロトタイプ、本編設計、完成版候補、保留・対象外を区別します。

このタスクは「何を画面設計の候補として扱うか」を確定して、画面遷移を作る[PB-TASK-0047](/tasks/ui/pb-task-0047)と、ラフ下絵を作る[PB-TASK-0048](/tasks/ui/pb-task-0048)へ渡すタスクです。画面遷移図やラフ下絵の完成は、本タスクの完了条件に含めません。

## 成果物

成果物は[想定画面一覧・画面遷移](/spec/ui/screen-inventory)のうち、画面一覧、対象範囲の説明、保留・対象外の記録です。

初回一覧では、次の22画面IDを扱います。

| 区分 | 画面ID | 項目数 |
|---|---|---:|
| プロトタイプ | `UI-001`～`UI-006` | 6 |
| 本編設計対象 | `UI-101`～`UI-111` | 11 |
| 完成版候補 | `UI-201`～`UI-204` | 4 |
| 保留 | `UI-301` | 1 |

ID未付与の保留・対象外候補も、採用済みの画面と混同しないよう理由を記録します。画面を追加・統合・削除する場合は、変更理由と後続タスクへの影響を同じページへ追記します。

## 実施内容

### 1. 正本を確認する

ゲーム全体、プロトタイプ、UI、入力、拠点、Mode／Conduct、演奏、ラジクジラ等の仕様を確認し、仕様で確定している機能と画面化の案を区別します。

### 2. 画面を一覧化する

各画面IDに、少なくとも次を記載します。

| 項目 | 記載内容 |
|---|---|
| 画面ID・名称 | 資料間で同じ対象を識別できる名称 |
| 目的 | Playerが確認・実行すること |
| 対象範囲 | プロトタイプ必須／任意／本編設計対象／完成版候補／保留・対象外 |
| 入口・出口 | どの状態から入り、どこへ進むか |
| 主な表示情報 | Playerの判断に必要な情報 |
| 主な操作 | Keyboard／Mouseで必要な操作 |
| 状態差分 | Loading、Empty、Locked、Error等の候補 |
| 未決事項 | 仕様確認や判断が必要な内容と確認先 |

施設や機能の採用と、独立画面の採用は区別します。1施設につき1画面を自動的に追加せず、タブ、Overlay、世界内表示へまとめる可能性を残します。

### 3. 保留・対象外を記録する

保留・対象外の候補には、現時点で採用しない理由と、再検討時に決める項目を記載します。採用が決まる前に、詳細レイアウトや実装方式を確定しません。

### 4. 未決事項と後続への影響を整理する

一覧化の途中で見つかった仕様不足に、確認先または判断担当を記載します。画面遷移に影響する内容はPB-TASK-0047へ、ラフの情報量や状態差分に影響する内容はPB-TASK-0048へ渡します。

### 5. 関係者レビューを行う

企画、デザイン、プログラム担当で、画面の漏れ・重複、対象範囲、正本との不一致、後続タスクへ渡す未決事項を確認します。

## 対象外

- 完成版・プロトタイプの画面遷移図の完成
- 低解像度ラフ、詳細Wireframe、最終UIデザイン
- UI Toolkit／uGUI等によるRuntime実装
- 仕様で未確定のGameplay内容や入力操作の独自決定
- 個人の担当、期限、進捗の公開仕様への記載

## 完了条件

- [ ] `UI-001`～`UI-006`、`UI-101`～`UI-111`、`UI-201`～`UI-204`、`UI-301`の22画面IDが一覧にある
- [ ] 22画面すべてに名称、目的、対象範囲、入口・出口、主な表示情報、主な操作、状態差分、未決事項が記載されている
- [ ] プロトタイプ必須／任意、本編設計対象、完成版候補、保留・対象外の意味が説明されている
- [ ] 施設・機能の採用と、独立画面の採用を混同していない
- [ ] ID未付与の保留・対象外候補に、採用済みではないことと判断理由が記載されている
- [ ] 未決事項に確認先または判断担当が記載されている
- [ ] 企画、デザイン、プログラム担当のレビュー結果が記録されている
- [ ] PB-TASK-0047とPB-TASK-0048へ渡す未決事項・参照先が記録されている

## 確認手順

1. 画面IDを数え、初回一覧が22項目であることを確認します。
2. 各行を左から確認し、完了条件に挙げた項目が空欄になっていないことを確認します。
3. ゲーム全体、プロトタイプ、UI、拠点、Mode／Conduct、演奏、ラジクジラの各正本と照合します。
4. プロトタイプ任意、完成版候補、保留・対象外が、プロトタイプ必須として読めないことを確認します。
5. 未決事項と確認先をPB-TASK-0047・PB-TASK-0048の担当者が受け取れることを確認します。
6. 企画、デザイン、プログラム担当のレビュー記録を確認します。

## 前提・依存タスク

なし。Gameplay Runtimeや画面ラフの完成を待たず、現行仕様と仮情報で着手できます。

PB-TASK-0047とPB-TASK-0048は、本タスクでレビュー済みとなった画面IDと対象範囲を引き継ぎます。

## 提出・報告方法

1. 更新した画面一覧のページまたはPull RequestをNotionタスクへ記載します。
2. レビュー結果、未決事項、PB-TASK-0047・PB-TASK-0048への引継ぎ内容をNotionタスクへ記載します。
3. 仕様へ反映が必要な決定事項は、対象ページと追記内容が分かる形で添付します。

### レビュー・引継ぎの記録 {#review-record}

企画・デザイン・プログラムの各確認結果を、Notion等の内部管理先へ次の項目で記録します。チェックリストの存在、資料の追加、PRのマージだけで関係者レビューの完了にはしません。

- 対象資料のURL・Commitまたは版、確認日
- 確認した役割、確認項目、結果、指摘と対応結果
- レビュー済みの画面ID・対象範囲（PB-TASK-0047では入口・出口も含む）
- 残る未決事項のID・確認先・決定が必要な時点・後続で継続できる範囲
- 後続タスクへ渡す資料のリンク

未実施・記録未確認・差戻しは承認と区別します。個人名・個人の期限・進捗は公開仕様へ転記しません。

## 実装・成果記録

### 2026-09-11｜想定画面一覧（22画面）

- できるようになったこと：想定する22画面を画面ID・名称・役割・対象区分で一覧にし、後続の画面遷移とラフ制作で扱う対象を確認できるようにした。
- 実装・制作方法：[PR #85](https://github.com/pushpush-ehime/palette-bullet-docs/pull/85)で作成し、[PR #88](https://github.com/pushpush-ehime/palette-bullet-docs/pull/88)で引継ぎ情報を補足した既存一覧を、以下の表にまとめた。画面IDの追加・統合・削除は行っていない。
- 成果物：本記録の想定画面一覧と保留・対象外一覧。各画面の入口・出口、表示情報、操作、状態差分は[想定画面一覧・画面遷移](/spec/ui/screen-inventory)を参照する。
- 確認した操作・テスト・版と結果：[確認元の一覧（b07e9dd）](https://github.com/pushpush-ehime/palette-bullet-docs/blob/b07e9dd4663c10d1f7531b0dfa5a609c55d8f8f6/docs/spec/ui/screen-inventory.md)と照合し、22画面IDの重複・欠落がなく、対象区分とID未付与の5項目を引き継いでいることを確認した。
- 実接続／Fake：対象外。今回の成果物は画面設計用の一覧資料であり、ゲームの実接続やFakeによる動作確認を扱わない。
- 制限・残作業・対象外：機能の採否や未決のGameplay仕様は本記録で確定しない。画面遷移の確定はPB-TASK-0047、ラフ制作はPB-TASK-0048で扱う。画面の実装・ラフ完成を示す記録ではない。

以下の「画面」は、全画面のほかHUD・会話パネル・タブ・Overlayを含む、情報と操作のまとまり。22枚の独立画面を作る決定ではなく、複数IDを一つの画面にまとめる場合もIDとの対応を残す。

#### プロトタイプ必須：3画面

Battleプロトタイプに必要な画面。PB-TASK-0048の初回ラフ対象。

| 画面ID | 画面名 | 何をする画面か |
|---|---|---|
| UI-001 | Battle画面・HUD | 戦況と次の操作を判断する。通常Charge→発射→浄化を先に扱い、Mode／Conductの表示は追加段階で扱う |
| UI-002 | 共通Result | Clear／Game Overの結果と次の操作を示す。ClearはContinueだけ、Game OverはRetryだけを表示する |
| UI-003 | 必須機能失敗・再起動案内 | 必須準備・cleanupの失敗による中断を知らせ、アプリの終了・再起動を案内する。通常のGame Overとは別で、Retry／Continueで復旧しない |

#### プロトタイプ任意：3画面

採用する場合に設計する補助画面。プロトタイプの完成条件には含めず、初回ラフの対象外。

| 画面ID | 画面名 | 何をする画面か |
|---|---|---|
| UI-004 | 起動・読み込み・準備中表示 | 準備や遷移を待っていることを知らせる。準備処理は必須だが、独立したロード画面の採用は未決 |
| UI-005 | Pauseメニュー | 一時停止中であることを示し、元のゲーム画面へ戻る。採用場面と項目は未決 |
| UI-006 | 操作説明・チュートリアル案内 | 操作方法、今行うこと、操作結果を説明する。プロトタイプでは配布物の操作説明でもよく、専用画面は任意 |

#### 本編設計対象：11画面

拠点・演奏等の本編UIとして設計する対象。PB-TASK-0048の初回ラフに含めるが、Battleプロトタイプへの実装を必須にするものではない。専用画面の要否や機能の実装時期は未決。

| 画面ID | 画面名 | 何をする画面か |
|---|---|---|
| UI-101 | 拠点の探索画面・HUD | 町を移動し、話せる人や使える施設を判断する |
| UI-102 | NPC・ギルド職員との会話 | 会話を進め、困りごとや依頼を知る |
| UI-103 | クエスト一覧・詳細・受注 | 挑戦できる依頼の内容を確認し、受注する |
| UI-104 | Stage選択・出発準備 | 行き先と必要な準備内容を確認し、出発する |
| UI-105 | 調律工房・Mode構成編集 | Mode構成を確認・編集する。Mode 1は編集不可、Mode 2～4は最大3スロット。Stage中やPauseからは構成編集しない |
| UI-106 | 調律工房・Conduct設定 | Conductに関する準備内容を確認する。工房で設定する範囲と独立画面の要否は未決 |
| UI-107 | 試走スペースの画面・補助HUD | 調整した内容や動きを試し、結果を確認する。試せる機能や専用UIの要否は未決 |
| UI-108 | レコード販売所・商品一覧／詳細 | レコードの品揃えと内容を確認し、購入する。通貨・価格・試聴等は未決 |
| UI-109 | 曲選択・演奏準備 | 演奏する曲と使用する設定を確認する。選曲方法は未決で、当面は用意済みの曲・設定でもよい |
| UI-110 | 演奏中の画面・最小HUD | ラジクジラの単独自動演奏を鑑賞し、終了・再開始する |
| UI-111 | ラジクジラの行動パターン設定 | 用意された行動の順番と継続小節数を設定する。編集解放はストーリークリア後で、解放前は既定追従を使う |

#### 完成版候補：4画面

ゲーム全体の構成や利便性から挙げた候補。採用・仕様は未決で、初回ラフの対象外。

| 画面ID | 画面名 | 何をする画面か |
|---|---|---|
| UI-201 | タイトル・ゲーム開始 | ゲームの開始方法を選ぶ。タイトル画面の要否と表示項目は未決 |
| UI-202 | 設定／音量・表示等のタブ | プレイ環境を調整する。設定項目・適用方式は未決 |
| UI-203 | セーブ・ロード／データ管理 | 採用する保存方式に応じて進行データを扱う。手動画面の要否や自動保存との関係は未決 |
| UI-204 | クレジット | 制作者・使用素材等を表示するための候補。専用画面の採用・表示内容・入口は未決 |

#### 保留：1画面

機能自体の採否が未決。初回ラフの対象外。

| 画面ID | 画面名 | 保留理由・採用時に決めること |
|---|---|---|
| UI-301 | ラジクジラのレベルアップ画面 | 機能の採用は開発状況次第。入口・戻り先、成長内容、必要条件・消費物、操作、上限・不足状態は未決 |

#### ID未付与の保留・対象外：5項目

以下は22画面に数えず、初回ラフにも含めない。確認先は企画・各機能担当で、採用する場合に目的・情報・操作・入口・出口・状態差分を具体化して画面IDを付与する。

| 項目 | 扱い | 理由 |
|---|---|---|
| 音楽・演出設定の投稿、共有一覧、他Playerとの同時参加 | 現時点の対象外 | 当面の完成条件に共有を含めない |
| コンテストのエントリー・採点・ランキング | 保留 | コンテスト機能の採用が未確定 |
| モード連動ライティングの編集画面 | 保留 | 照明変化は検討メモで、専用エディタを作る決定ではない |
| 任意音源の取込・アップロード | 保留 | 曲の取込方式は未決。演奏広場の最初の接続には用意済みの曲を使える |
| 楽器・雑貨店の専用UI | 保留 | 施設自体が未確定で、現在の拠点図では配置対象外 |

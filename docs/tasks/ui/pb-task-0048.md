# PB-TASK-0048｜対象画面の低解像度ラフ制作

## タスクの目的

[PB-TASK-0026](/tasks/ui/pb-task-0026)の画面一覧と[PB-TASK-0047](/tasks/ui/pb-task-0047)の画面遷移を使い、Playerが確認する情報、主要操作、状態差分、画面間のつながりを相談できる低解像度ラフを作成します。

このタスクでは最終デザインを決めません。仕様に書かれていないGameplay内容をラフだけで確定せず、実装前に決める必要がある項目を発見して関係者へ渡します。

## このタスクでラフを完成させる画面

| 扱い | 画面ID | 必要な成果物 |
|---|---|---|
| ラフ作成必須 | `UI-001` | 1920×1080基準のBattle画面・HUDラフ。通常状態を基準に、対象なし、Charge中・成否、操作不可、Battle終了、Mode／Conduct追加段階の差分を記録する |
| ラフ作成必須 | `UI-002` | 共通Resultの遷移上の位置と概要ラフ。Clear／Game Overの状態別詳細、Focus、操作lockの詳細WireframeはPB-TASK-0022へ委ねる |
| ラフ作成必須 | `UI-003` | 必須機能失敗時の中断・再起動案内の概要ラフ。通常のGame Over／Retryと区別でき、失敗した機能・段階・短い理由と終了・再起動案内を確認できるようにする |
| ラフ作成必須 | `UI-101`～`UI-111` | 各画面IDの目的、主な情報、主要操作、入口・出口が分かるThumbnailまたは手描き相当の低解像度ラフ |
| 今回はラフ対象外 | `UI-004`～`UI-006`、`UI-201`～`UI-204` | PB-TASK-0026の一覧とPB-TASK-0047の遷移まで。採用後にラフが必要になった場合は、後続タスクを作るか本表を更新してから着手する |
| ラフ対象外 | `UI-301`、ID未付与の保留・対象外項目 | 保留・対象外の理由を参照し、ラフは作成しない |

複数IDを一つの画面、タブ、Overlay等へまとめる案では、1IDにつき1画像を必須にしません。ただし、どのラフが各画面IDを扱うかを対応表または注記で追跡できるようにします。

## 実施内容

### 1. `UI-001`～`UI-003`を作成する

- `UI-001`は1920×1080・Keyboard／Mouseを基準にし、仮HUD、照準、選択、Charge、攻撃に必要な情報の配置候補を示す
- `UI-001`は通常のCharge→発射→浄化を先に確認し、Mode／Conduct追加段階と区別する
- `UI-002`は本タスクでは概要ラフまでとし、PB-TASK-0022が担当する状態別詳細を重複して作らない
- `UI-003`は必須機能失敗時の中断案内とし、通常のGame Over、Retry、Continueを追加しない

### 2. `UI-101`～`UI-111`を作成する

拠点、会話、依頼、出発準備、工房、試走、販売所、演奏準備・鑑賞、行動設定について、情報量と主要操作が分かる低解像度ラフを作成します。

施設ごとに独立画面を作る前提を置かず、一覧・詳細、タブ、Overlay、世界内表示としてまとめる案を比較できます。統合する場合も、対象となる全画面IDを記録します。

### 3. 状態差分と仮情報を記録する

通常、対象なし、情報なし、未解放、待機、使用不可、Error等、各画面に必要な状態差分を同じ画面IDへまとめます。仮文言、仮Icon、仮色は、確定仕様と誤認されないように注記します。

### 4. ラフと画面IDを対応付ける

画面一覧の各対象IDから、初稿画像と編集元を開けるようにします。個別UIページまたは複数画面をまとめた資料のどちらでも構いませんが、画面ID、参照仕様、入口・出口、主要操作、状態差分、確定事項、未決事項と確認先を記録します。

### 5. 関係者レビューを行う

企画、デザイン、プログラム担当で、情報の漏れ・過剰、入力との競合、画面遷移との一致、仮情報と確定仕様の区別、後続タスク候補を確認します。

## 対象外

- `UI-301`とID未付与の保留・対象外項目のラフ制作
- PB-TASK-0022が担当するResult画面の状態別詳細Wireframe
- 最終品質のUIデザイン
- Logo、Font、Icon、色、Animation、VFXの最終決定
- UI Toolkit／uGUI等によるRuntime実装
- ゲームパッド用の詳細Focus移動設計
- 仕様で未確定のGameplay情報や数値の独自決定

## 確認手順

1. `UI-001`～`UI-003`、`UI-101`～`UI-111`の各IDから対応するラフを開きます。
2. 複数IDをまとめた案では、対応表または注記に全対象IDがあることを確認します。
3. 1920×1080基準で、`UI-001`～`UI-003`の主要情報と主要操作が画面外へ欠けていないことを確認します。
4. PB-TASK-0047の入口・出口と各ラフの記載を照合します。
5. UI-002の詳細成果物がPB-TASK-0022と重複していないことを確認します。
6. 仮情報、未決事項、確認先、後続タスク候補を確認します。
7. 企画、デザイン、プログラム担当のレビュー記録を確認します。

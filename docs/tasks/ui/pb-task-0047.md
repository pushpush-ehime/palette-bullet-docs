# PB-TASK-0047｜完成版・プロトタイプ画面遷移図の確定

## タスクの目的

[PB-TASK-0026](/tasks/ui/pb-task-0026)で確定した画面IDを使い、完成版とプロトタイプの画面遷移を別々にたどれる状態にします。通常のClear／Game Overと、必須機能失敗時の中断を混同せず、入口、主要操作、出口、戻り先、未決の受け先を図と文章で確認できるようにします。

このタスクは遷移を確定・記録するタスクです。各画面のレイアウトや見た目を決めるラフ制作は[PB-TASK-0048](/tasks/ui/pb-task-0048)で行います。

## 成果物

[想定画面一覧・画面遷移](/spec/ui/screen-inventory#画面遷移)に、次の2系統の遷移図と補足説明を記載します。

1. 完成版：`ゲーム開始 → 拠点 → 依頼・準備 → Battle → Result → 次の行き先`
2. プロトタイプ：`起動 → Battle準備 → Battle → 共通Result`から、ClearとGame Overそれぞれの出口

## 実施内容

### 1. プロトタイプの遷移を作成する

少なくとも次を一続きで図示します。

- 起動からBattle準備、`UI-001` Battle画面・HUDまで
- Battle結果確定から`UI-002`共通Resultまで
- Clear：操作lock、解禁、Continue、Gameが定める受け先
- Game Over：操作lock、解禁、Retry、新しいBattle準備、`UI-001`への復帰
- 必須準備・cleanup失敗：`UI-003`中断・再起動案内、アプリ終了・再起動
- `UI-004`～`UI-006`は採用時だけ使う任意経路であり、必須経路へ含めないこと

Clear後のプロトタイプ上の具体的な受け先が未決でも、本タスクは完了できます。その場合は、仮の受け先を独自決定せず、未決であること、判断担当、実装前に決定する期限を記録します。ClearへRetryを追加して解決しません。

### 2. 完成版の遷移を作成する

少なくとも次を図示します。

- ゲーム開始候補から`UI-101`拠点探索への入口
- 会話、依頼確認・受注、Stage選択・出発準備、Battleへの導線
- 調律工房、試走スペース、レコード販売所、演奏広場への出入り
- 演奏準備、自動演奏・鑑賞、行動パターン設定の関係
- Battle後のClear／Game Overと、拠点・Stage選択・現在Stage Retryの関係

施設と画面を1対1に固定せず、タブや同一画面へ統合する案は未決として表現します。

### 3. 入口・出口・戻り先を照合する

遷移図の各画面IDをPB-TASK-0026の一覧と照合します。図にのみ存在する画面を作らず、一覧にない画面が必要になった場合はPB-TASK-0026へ戻して画面IDと理由を追加します。

### 4. 未決事項と後続への影響を整理する

受け先、戻り先、閉じる操作、未保存変更、機能解放時期等の未決事項に、確認先または判断担当を記載します。ラフで比較する必要がある内容はPB-TASK-0048へ渡します。

### 5. 関係者レビューを行う

企画、デザイン、プログラム担当で、主要フローが途中で切れないこと、任意画面が必須化されていないこと、UIとGameの責任境界が正本と一致することを確認します。

## 対象外

- 画面一覧22項目の洗い出し・分類のやり直し
- 低解像度ラフ、詳細Wireframe、最終UIデザイン
- Scene、Prefab、UI Toolkit／uGUI等のRuntime実装
- Clear後の未決受け先や、任意画面の採用を本タスクだけで決定すること

## 完了条件

- [ ] 完成版とプロトタイプの遷移図が別々に記載されている
- [ ] プロトタイプを`起動 → Battle準備 → UI-001 → UI-002`までたどれる
- [ ] Clearは`Continue → Gameが定める受け先`、Game Overは`Retry → 新しいBattle準備`として区別されている
- [ ] 必須準備・cleanup失敗が`UI-003 → 終了・再起動`として通常のGame Over／Retryと区別されている
- [ ] `UI-004`～`UI-006`が任意であり、プロトタイプの必須経路へ含まれていない
- [ ] 完成版で`UI-101`～`UI-111`の入口・出口・主要なつながりをたどれる
- [ ] 図中の画面IDがPB-TASK-0026の一覧と一致し、IDなしの画面が暗黙に追加されていない
- [ ] 未決の受け先・戻り先に、確認先または判断担当と決定が必要な時点が記載されている
- [ ] PB-TASK-0048へ渡す遷移上の注意点が記録されている
- [ ] 企画、デザイン、プログラム担当のレビュー結果が記録されている

## 確認手順

1. プロトタイプのClear経路とGame Over経路を起動から終点まで別々にたどります。
2. 必須機能失敗経路がResultへ合流せず、終了・再起動へ進むことを確認します。
3. 完成版で拠点から依頼・Battle・Result・拠点への主要な循環をたどります。
4. 拠点の各施設と演奏広場の入口・出口をたどります。
5. 図中の画面IDをPB-TASK-0026の一覧と照合します。
6. 未決事項、確認先、決定時点と、PB-TASK-0048への引継ぎを確認します。
7. 企画、デザイン、プログラム担当のレビュー記録を確認します。

## 提出・報告方法

2. Notionタスクへ共有リンク、レビュー結果、未決事項、決定が必要な時点を記載します。
3. PB-TASK-0048へ、ラフで確認する入口・出口・状態差分を引き継ぎます。

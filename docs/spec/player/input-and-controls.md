# Player入力と操作
### 基本設計方針（キーバインド・マッピング）

**絶対の原則**

「入力デバイスの特定のボタン（キー）とアクションを直接紐づけない（ハードコードしない）こと」

*   **アクションマッピングの採用:** 「Jumpアクションが入力された」「Attackアクションが入力された」といった抽象化されたアクション名でイベントを受け取れるように設計してください。
*   **キーコンフィグの前提:** 将来的にプレイヤーがオプション画面で自由にボタン配置（キーバインド）を変更できる状態を前提として実装を進めてください。
*   **マルチデバイス想定:** キーボード＆マウス、各種ゲームパッドなど、入力元が変わってもPlayerのスクリプト自体は一切変更せずに動く状態を目指します。

### デフォルトの入力割当

以下はアクションマッピングにおけるデフォルトのバインドです。

ドローモード中はマウス移動が「カメラ操作」と「シャオンダマのなぞり」を兼ねる。画面上を自由に動くカーソルは使わず、**画面中央のレティクル**が選択位置となる（[ドローモード時のカメラ](/spec/camera/draw-mode)）。

| 操作 | 入力 | 状態 |
|---|---|---|
| 移動 | `W` `A` `S` `D` | 確定 |
| ダッシュ（回避） | デフォルト設定はShift | 仮仕様 |
| カメラ操作 | マウス移動 | 仮仕様 |
| ドローモード開始 | 右クリック | 仮仕様 |
| シャオンダマのなぞり | 左ボタンを押したままマウス移動（カメラを振る） | 仮仕様 |
| ドローモード確定・終了 | 右クリック | 仮仕様 |
| マーカー発射 | マウスホイール押し込み | 確定 |
| 万能シャオンダマ生成スキル | `Q` | 仮仕様 |

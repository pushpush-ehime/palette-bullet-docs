# ラジクジラ｜シャオンダマ生成

## 目的

本ページでは、**Normal Shaondamaおよび最低保証補充Wildcardについて、ゲームシステム側から生成要求を受け取った後、論理生成、出現演出、出現演出完了、Gameplayへの制御移譲、および選択可能化まで**を定義します。

本ページを、生成要求から出現演出完了・選択可能化までの状態境界と、Battle開始Readyへ接続する完了通知の正本とします。

ラジクジラは、シャオンダマの生成対象・生成タイミング・生成個数を判断しません。

生成に関する責務は、次のように分離します。

```text
BGM / MusicChart
「何を・いつ・何個生成するか」を決定
        ↓
Spawn System
生成要求
        ↓
ラジクジラ
生成要求を論理個体と世界内の出現へ変換
        ↓
シャオンダマ
出現演出完了後の浮遊・Lifetime・終了等を担当
```

本ページでは、このうち**ラジクジラが生成要求を受け取り、シャオンダマを背中側から世界内へ出現させ、選択可能なGameplay個体として制御を移譲するまで**を正本として扱います。

生成対象、生成個数、生成タイミング、最低保証数、不足数の算出は[BGM→シャオンダマ生成仕様](../bgm/bgm-make-syaonndama.md)を正本とします。出現完了後の浮遊、Lifetime、Reserved、自然破裂、消滅は[浮遊・挙動](../shaondama-music/floating-behavior.md)を正本とします。

本ページの共通状態遷移は、Normal Shaondamaと、最低保証不足を生成元とするWildcard Shaondamaの出現要求にだけ適用します。

Parry由来Wildcardは、Parry成立時点のworld位置で即座に変換され、変換commitと同時に選択可能になります。そのため、本ページのRadioWhale通常受付へ合流させず、論理生成、姿勢変更、背中側Spawn、一定時間の出現演出、出現演出完了通知、およびGameplayへの制御移譲を適用しません。変換後のWildcardへ加える弾き方向の力と、その後の移動もRadioWhaleは管理しません。

## ラジクジラが担当する生成範囲

ラジクジラが担当する範囲は、Normal Shaondamaおよび最低保証補充Wildcardについて、外部のSpawn Systemから生成要求を受け取ってから、論理個体を作成し、シャオンダマを世界内へ出現させ、出現演出完了時にGameplayへ制御を移譲して選択可能にするまでです。

基本的な流れは以下です。

```text
外部Spawn System
        ↓
生成要求
        ↓
論理生成
        ↓
出現演出中
├─ ラジクジラが少し姿勢を変更
└─ 背中側からシャオンダマを出現させる
        ↓
出現演出完了
        ↓
Gameplayへ制御移譲
        ↓
選択可能
```

ラジクジラ自身がMusicChartやNoteEventを解析して生成対象や生成タイミングを決定することはありません。

また、ラジクジラが担当するのは**シャオンダマを生み出し、出現演出を完了して選択可能化するところまで**です。

世界内へ出現した後のシャオンダマの挙動は、[シャオンダマ](../shaondama-music/)カテゴリを正本とします。

## 生成要求の受信

ラジクジラは、外部のSpawn Systemからシャオンダマの生成要求を受け取ります。

本ページで受理する生成要求は、少なくとも以下の2種類です。

| 生成要求 | 上流での決定 | 本ページの処理 |
|---|---|---|
| Normal生成要求 | MusicChartのsource NoteEvent occurrenceに基づき、BGM生成側が対象・時刻・個数を決定 | 要求されたNormalを論理生成し、ラジクジラから出現させる |
| 最低保証不足によるWildcard補充要求 | BGM生成側が現在選択可能数と補充要求中数から不足数を決定 | 要求された不足数分のWildcardを論理生成し、出現させる |

Parry由来Wildcardはこの2種類とは別の生成元です。本ページの通常受付へ合流させず、RadioWhaleはParry変換要求を通常生成要求として受理・再発行しません。

生成要求を受信した時点では、ラジクジラ側で、

* 対象Trackを選択する
* NoteEventを選択する
* 生成する個数を決定する
* 生成タイミングを決定する
* BGMとの同期位置を計算する

といった判断は行いません。

これらはBGM / MusicChart側の責務です。

ラジクジラは、上流システムですでに決定された生成内容を、**世界内での出現へ変換する役割**を持ちます。

生成要求の受理時は、少なくとも次を確認します。

- Battle IDが現在のBattleと一致している
- 生成要求を一意に識別できる
- Shaondama種別と生成元区分を識別できる
- 要求個数が確定している
- Normalでは、個体へ引き継ぐsource NoteEvent occurrence情報が揃っている

必須情報が欠けている要求、旧Battle IDの要求、すでに終了したBattleの要求は有効化しません。

同じ生成要求を再受信しても、同じBattle内で2回目の論理個体を作成しません。要求識別情報とBattle IDを使用し、受付、論理生成、演出開始、演出完了通知を冪等に扱います。具体的なIDの型や採番方式は固定しません。

## 生成要求に含まれる情報

生成要求の具体的なフィールド名・型・保存形式は、本ページで固定しません。

生成要求として下流へ渡すデータの詳細は、BGM側の生成仕様を正本とします。

本ページでは、ラジクジラが生成要求を受信した後に、その要求内容を欠落させず論理個体へ引き継ぎ、世界内への出現処理と選択可能化を行うことを定義します。

ラジクジラ側で生成要求を補完するためにMusicChartを再解析したり、生成対象・生成個数・生成タイミングを再決定したりしないものとします。

## 状態遷移

本ページが管理するNormal Shaondamaおよび最低保証補充Wildcardの基本状態遷移は、以下を正とします。Parry由来Wildcardはこの状態遷移へ入りません。

```text
生成要求
↓
論理生成
↓
出現演出中
↓
出現演出完了
↓
Gameplayへ制御移譲
↓
選択可能
```

| 状態・境界 | 論理個体 | world表示 | Player選択 | 最低保証数への算入 | 主な処理 |
|---|---|---|---|---|---|
| 生成要求受信 | 未作成 | なし | 不可 | 算入しない | Battle ID・要求識別情報・必須dataを検証する |
| 論理生成 | 作成済み | 未表示または演出準備中 | 不可 | 算入しない | 個体識別情報を割り当て、要求dataを引き継ぐ |
| 出現演出中 | 作成済み | 出現途中 | 不可 | 算入しない | 姿勢変更、背中側からの出現、VFX等を進行する |
| 出現演出完了 | 作成済み | world内へ出現済み | 完了処理中 | まだ算入しない | 演出完了を一度だけ確定する |
| 制御移譲・選択可能 | 作成済み | world内に存在 | 可 | 非`Reserved`なら算入する | Gameplayへ制御を渡し、選択可能化を通知する |

### 論理生成

生成要求を受理した後、要求された個数分の論理個体を作成します。

- 各個体へ一意な個体識別情報を割り当てます。
- Battle ID、生成要求識別情報、Shaondama種別、生成元区分を引き継ぎます。
- Normalではsource NoteEvent definition／occurrence、source music time、音程、Track等の必須dataを引き継ぎます。
- 最低保証不足によるWildcardでは、その生成元区分と補充要求との対応を保持します。
- 論理生成済みであっても、出現演出完了前はPlayerへ公開しません。

個体dataの正本は[玉のデータ](../shaondama-music/orb-data.md)とし、本ページで音程・色・Damage等を再計算しません。

### 出現演出中

RadioWhale経路で論理生成したNormal Shaondamaおよび最低保証補充Wildcardを、出現演出中へ移します。

- 出現演出中の個体は選択不可です。
- Charge対象検索、Click／Dragの保持対象、およびAllocation候補へ含めません。
- 最低保証数へ算入しません。
- 論理個体や一部表示objectが存在していても、出現完了済みとして扱いません。
- 同じ個体について出現演出を重複開始しません。

出現演出中の個体を先に選択可能にし、後から見た目だけ追いつかせる処理は採用しません。

### 出現演出完了・選択可能化

RadioWhale経路の個体ごとの出現演出が完了した時点で、次の処理を順に一度だけ行います。

1. 対象Battleが継続中であり、個体のBattle IDが現在のBattleと一致することを確認する
2. 対象個体の出現演出完了を確定する
3. ラジクジラ／出現処理からShaondama Gameplayへ制御を移譲する
4. 対象個体をPlayerの選択対象として公開する
5. 選択可能化完了を、最低保証判定を所有する上流へ通知する

制御移譲と選択可能化は、出現演出完了境界で接続します。通常の完了処理において「出現演出完了済みだが、理由なく選択不可のまま待機する」中間状態を設けません。

出現完了後の浮遊、一般Lifetime、Normalのsource NoteEvent時刻、Reserved、自然破裂、消費、Battle終了時のGameplay無効化は[浮遊・挙動](../shaondama-music/floating-behavior.md)を正本とします。

## 生成元

本ページで受理したNormal Shaondamaと最低保証不足によるWildcard Shaondamaは、**ラジクジラの背中側から世界内へ出現します**。

ラジクジラは生成時に少し姿勢を変更し、その後、背中からシャオンダマを吹き出す形で出現させます。

本ページで定義するのは、

* 生成時に姿勢変更が発生すること
* 背中側がシャオンダマの出現元となること

までです。

具体的なAnimation、VFX、SE、鳴き声などの演出内容は、本ページでは定義しません。

これらの詳細は[ラジクジラ｜Animation・VFX・Sound](./animation-effects-sound.md)を正本とします。

また、背中のどの位置を具体的なSpawn位置とするかは未決です。

最低保証不足によるWildcardの生成契機、生成元区分、Wildcard固有dataは[万能シャオンダマ](../shaondama-music/wildcard-orb.md)を正本とします。本ページは、上流でWildcardとして確定した補充要求を受け、要求個数分を出現演出完了・選択可能化まで処理します。

Parry由来Wildcardは邪音玉のParry成立位置で即時変換され、変換commitと同時に選択可能になるため、ラジクジラの背中側から出現する本経路へ置き換えません。Parry由来Wildcardのために、Normal Shaondamaまたは最低保証補充Wildcardの既存Spawn経路を変更しません。

## 単体生成

1体のシャオンダマを生成する要求を受けた場合も、ラジクジラは通常の生成処理として扱います。

```text
生成要求
        ↓
論理生成
        ↓
ラジクジラの姿勢変更
        ↓
背中側からシャオンダマを出現
        ↓
出現演出完了
        ↓
Gameplayへ制御移譲・選択可能化
```

生成対象・生成タイミングをラジクジラ側で再判断することはありません。

また、選択可能化後の浮遊・Lifetime・消滅・Reserved等の挙動はラジクジラ側では管理しません。

## 複数生成

複数のシャオンダマを生成する要求についても、要求個数分をラジクジラを介して世界内へ出現させます。

複数生成の場合も、

* 生成する個数の決定
* 生成対象の決定
* 生成タイミングの決定

はラジクジラ側の責務ではありません。

ラジクジラは、受け取った生成要求に従ってシャオンダマを背中側から出現させます。

最低保証不足によるWildcard補充要求では、上流が確定した不足数を要求個数として受け取り、その個数分を論理生成・出現させます。ラジクジラ側で不足数を再計算したり、要求個数を独自に増減したりしません。

複数個体は、各個体の出現演出完了ごとに個別に制御移譲・選択可能化します。Batch全体の最後まで、先に出現完了した個体を一律に選択不可のまま待機させません。

複数生成時の各個体の出現演出時間には同じ調整パラメータを使用します。各個体の出現開始間隔や、視覚的に完全同時または連続噴出のどちらで見せるかの詳細は未決です。

## 出現演出時間

RadioWhale経路のNormal Shaondamaおよび最低保証補充Wildcardには、論理生成後から出現演出完了まで一定の出現演出時間を設けます。Parry由来Wildcardには適用しません。

- 出現演出時間は調整可能な共通パラメータです。
- 具体的な秒数は未確定です。
- 個体ごとに出現演出開始から完了までを判定します。
- 出現演出時間が経過する前に選択可能化しません。
- AnimationやVFXの制作都合によって、上流が決めた生成対象・個数・生成タイミングを変更しません。

パラメータ名、内部timer、Animation Eventまたは時間比較のどちらで完了を検知するかは実装設計で決めてよいものとします。ただし、いずれの方式でも出現演出完了と選択可能化の境界を一致させます。

## Gameplayロジックと表示タイミングの分離

**RadioWhale経路におけるGameplay上の生成成立と、ラジクジラからシャオンダマが視覚的に出現するタイミングは、区別して扱います。**

ラジクジラの姿勢変更や背中から吹き出す表現は、上流で決定された生成内容を世界内へ表現するための処理です。

そのため、

```text
BGM / MusicChartによる生成内容の決定
```

と、

```text
ラジクジラによる視覚的な世界内出現
```

を同一の責務として扱いません。

具体的なAnimationやVFXの長さによって、BGM側の生成対象・生成個数・生成タイミングを再決定することもありません。

論理生成は、要求された個体を内部dataとして作成したことを意味します。Playerが利用できるGameplay個体としての成立境界は、出現演出完了後の制御移譲・選択可能化です。

```text
論理生成済み・未表示
→ 選択不可

出現演出中
→ 選択不可

出現演出完了
→ 制御移譲
→ 選択可能
```

したがって、視覚的に未出現または出現途中の論理個体を、レティクル検索、Charge、最低保証達成数へ先行利用しません。

## 生成中の追従

シャオンダマ生成とPlayer追従は、排他的なStateとして扱いません。

ラジクジラは**シャオンダマ生成中も通常のPlayer追従を継続します**。

生成処理を開始したことを理由として、Playerへの追従を停止しません。

ただし、

* 追従速度
* Playerとの距離
* 浮遊範囲
* 画面外での位置補正
* Stage Geometryとの関係

などの具体的な追従仕様は、本ページでは定義しません。

これらは[ラジクジラ｜追従・浮遊](./follow-and-floating.md)を正本とします。

## シャオンダマ側への制御移譲

ラジクジラが担当するのは、Normal Shaondamaおよび最低保証補充Wildcardを世界内へ出現させ、**出現演出完了時に**シャオンダマ側へ制御を移譲して選択可能にするところまでです。

制御移譲後の、

* 浮遊
* Lifetime
* 消滅
* 選択対象としての通常挙動

などは、[シャオンダマ](../shaondama-music/)カテゴリの責務です。

ラジクジラは、出現後のシャオンダマを自身の生成処理の一部として継続管理しません。

制御移譲timingは未決ではありません。出現演出完了を境界とし、完了前はラジクジラ／出現処理側、完了後はShaondama Gameplay側が責務を持ちます。

この制御移譲境界はRadioWhale経路だけに適用します。Parry由来Wildcardは変換commitと同時に選択可能なWildcard状態へ直接入るため、RadioWhaleからの制御移譲を待ちません。

## 最低保証数との接続

選択可能Shaondamaの最低保証数は、[BGM→シャオンダマ生成仕様](../bgm/bgm-make-syaonndama.md)が所有します。本ページは最低保証数や不足数を計算せず、個体ごとの状態を一意に通知します。

本ページのRadioWhale経路から最低保証数へ算入できるのは、以下をすべて満たす個体だけです。

- 出現演出が完了している
- Gameplayへ制御移譲済みである
- 現在Playerの選択対象として公開されている
- `Reserved`ではない
- 現在のBattle IDへ属している

論理生成済み、生成要求中、出現演出中の個体は算入対象外です。

### Battle開始Ready

Battle開始前は、個体を論理生成した時点や出現演出を開始した時点でShaondama準備完了を通知しません。

```text
必要数の生成要求
↓
論理生成
↓
出現演出中
↓
各個体が出現演出完了・選択可能化
↓
現在選択可能・非Reserved数を再集計
↓
最低保証数へ到達
↓
Shaondama Supply Ready
```

本ページは個体ごとの選択可能化完了を最低保証判定側へ通知します。最低保証判定側は、必要数が実際に選択可能になった後にのみShaondama Supply Readyを成立させます。

対象RoomのEnemy準備など、他のReady条件はGame／Stage／Combat側を正本とします。本ページからBattle／Gameplay／MusicChart時計を開始しません。

Normal Shaondamaを使用するBattleでは、RadioWhaleを必須とします。RadioWhaleを用意できていない状態、またはNormalの出現演出を完了できていない状態で、Normalを別経路から選択可能にしてBattle開始Readyを成立させません。

### Battle中の不足補充

Battle中に最低保証数を下回った場合は、上流から不足数分のWildcard補充要求を受け取ります。

- 要求された不足数分だけ論理個体を作成します。
- 各Wildcardへ最低保証不足による生成元区分を保持します。
- 各個体を出現演出中として処理し、演出完了前は選択不可・算入外とします。
- 各個体の演出完了時に制御移譲・選択可能化し、完了通知を返します。
- 同じ補充要求の再受信で個体数を重複させません。

出現演出中は、一時的に最低保証数を下回ることを許容します。不足補充を待つためにBattleや音楽時計を停止・巻き戻しません。

## Parry由来WildcardはRadioWhale責務外

Parry成功によって邪音玉から変換されるWildcardは、最低保証不足によるWildcard補充と生成元、生成位置、および選択可能化経路が異なります。

Parry由来Wildcardには、次の規則を適用します。

- Parry成功した邪音玉1弾につきWildcard 1個へ変換する
- 同一Physics Stepの成功batchに複数弾が含まれる場合も、各弾を個別のWildcardへ変換する
- 変換位置は、各邪音玉のParry成立時点のworld位置とする
- Parry成立位置で即座にWildcardへ変換commitする
- 変換commitと同時にPlayerのCharge対象として選択可能にする
- 変換直後に、Parry結果として対象ごとに確定した弾き方向の力を変換済みWildcardへ1回だけ加える
- 変換後のWildcardは選択可能なまま弾き移動し、選択可能かつ非`Reserved`であれば変換commit時点から最低保証数へ算入する
- Normal Parry／Just Parryによって、Wildcardの生成数、種別、選択条件、および弾き移動の基本性能を変えない

この経路はRadioWhaleの通常受付へ合流しません。RadioWhaleはParry由来Wildcardについて、次の処理を行いません。

- 通常生成要求としての受付または論理生成
- ラジクジラの姿勢変更
- 背中側Spawn
- 一定時間の出現演出と、その演出時間のtimer管理
- 出現演出完了通知
- Shaondama Gameplayへの制御移譲
- Parry由来Wildcardの選択可能化完了通知や最低保証算入通知
- 変換後のWildcardへの力の付与、弾き移動、減衰、または通常浮遊への接続

表示上の変換演出が続いていても、RadioWhaleの出現演出完了通知を待たず、Gameplay上は変換commit時点から選択可能です。

Parry由来Wildcardの変換条件、即時変換、即時選択可能化、および重複変換防止は[万能シャオンダマ](../shaondama-music/wildcard-orb.md)、Parry判定batchと対象ごとの弾き方向は[Playerアクション｜パリィ](../player/player-action-parry.md)、邪音玉としての終了と変換要求は[邪音玉](../enemy/jaon-bullet.md)、変換後の弾き移動・浮遊・Lifetime・`Reserved`・消費・Battle終了は[浮遊・挙動](../shaondama-music/floating-behavior.md)を正本とします。

本ページのNormal Shaondamaおよび最低保証補充Wildcardに対する通常受付、背中側Spawn、出現演出、完了通知、制御移譲、および選択可能化の規則は変更しません。

## Battle終了・Room Retry

### Battle終了

ClearまたはGame OverのBattle結果が確定した時点で、旧Battleに属する未完了の出現処理をGameplay上無効化します。

- 未受理・未実行の生成要求を開始しません。
- 論理生成済み・出現演出開始前の個体を選択可能にしません。
- 出現演出中の個体を最低保証数へ算入しません。
- Battle終了後に到着した演出完了callbackを無効とします。
- 旧Battleの選択可能化完了通知やReady通知を新しく発行しません。
- 遅延した旧Battleの要求・完了通知を別Battleへ適用しません。

見た目上の演出を即時消去するか、Damageを発生させない終了演出として短時間残すかは演出側で調整できます。ただし、いずれの場合もPlayer選択、Charge、最低保証、Damageへ接続しません。

### Room Retry

Room Retry時は、旧Battleに属する生成要求、論理個体、出現演出中object、要求処理状態、および完了通知予約をすべて破棄します。

新しいBattle IDを受領した後、新Battleの生成要求から状態遷移を最初から構築します。旧Battleの要求識別情報、論理個体、進行中timer、出現演出進捗、選択可能化通知を新Battleへ流用しません。

Room Retry地点と、Player／Enemy／BGM等の再初期化値はGame・Stage／Room側の正本へ委譲します。本ページは旧Battleの出現処理を持ち越さないことを保証します。

## BGM生成システムとの境界

シャオンダマ生成について、BGM側とラジクジラ側の責務は明確に分離します。

| 項目                      | 正本・担当            |
| ----------------------- | ---------------- |
| 対象Track                 | BGM / MusicChart |
| NoteEvent選択             | BGM / MusicChart |
| `1 NoteEvent = 1シャオンダマ` | BGM側のシャオンダマ生成仕様  |
| 選択可能Shaondamaの最低保証数・不足数 | BGM側のシャオンダマ生成仕様 |
| `MinimumLeadTime`       | BGM側のシャオンダマ生成仕様  |
| 生成対象の決定                 | BGM側のシャオンダマ生成仕様  |
| 生成個数の決定                 | BGM側のシャオンダマ生成仕様  |
| 生成タイミングの決定              | BGM側のシャオンダマ生成仕様  |
| 最低保証不足によるWildcard生成元・data | 万能シャオンダマ仕様 |
| BGMとの同期                 | BGM / MusicChart |
| 生成要求                    | Spawn System     |
| Normal／最低保証補充Wildcard生成要求の受信 | ラジクジラ            |
| Normal／最低保証補充Wildcardの論理生成・出現演出中state | 本ページ             |
| Normal／最低保証補充Wildcardの世界内への出現 | ラジクジラ            |
| Normal／最低保証補充Wildcardの背中側からの出現 | ラジクジラ            |
| Normal／最低保証補充Wildcardの出現演出完了・制御移譲・選択可能化 | 本ページ             |
| Normal／最低保証補充Wildcardの選択可能化完了通知 | 本ページ             |
| Parry判定batch・対象ごとの弾き方向 | Player Parry |
| 邪音玉としての終了・Wildcard変換要求 | 邪音玉 |
| Parry由来Wildcardの変換commit・即時選択可能化・重複変換防止 | 万能シャオンダマ。本ページの通常受付外 |
| Parry由来Wildcardの弾き移動・共通lifecycle | 浮遊・挙動。本ページの責務外 |

BGM側の生成ロジックについては、[BGM→シャオンダマ生成仕様](../bgm/bgm-make-syaonndama.md)を正本とします。

MusicChartおよびNoteEventなどの音楽データ構造については、[MusicChart](../bgm/bgm-music-chart.md)を正本とします。

ラジクジラはこれらの生成ロジックを複製せず、**上流で決定された生成要求を世界内でどう出現させるか**だけを担当します。

AttackEventは[AttackEvent](../bgm/bgm-attack-event.md)、選択可能化後のShaondamaをPlayerが扱うChargeは[Playerアクション｜チャージ](../player/player-action-charge.md)をそれぞれ正本とします。Charge側は、出現演出中の個体を選択対象として参照しません。

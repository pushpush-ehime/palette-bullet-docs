# ラジクジラ｜行動パターンと設定解放

## 目的

ラジクジラの移動を行動パターンとして扱い、初期追従、設定の解放条件、曲に合わせた再生、および各システムが受け渡す情報を定義します。

本ページでは、以下の確定事項と接続境界を正本とします。具体的な追加パターン、動きの数値、クラス名・API名・保存形式は未決です。

## 確定事項

- ラジクジラには行動パターンを設定する仕組みを用意します。
- **Player周辺を追従する動きも、一つの行動パターンです。**
- **最初のチュートリアルでは、この追従パターンを使用します。**
- **Playerによる行動パターン設定は、ストーリークリア後に解放します。**
- 設定解放前は既定の追従パターンを使用し、Playerによる組み替えを必須にしません。
- 解放後は、用意されたパターンを順に設定し、それぞれを何小節実行するかを指定する構成とします。
- 設定した曲の進行に合わせて、ラジクジラが行動パターンを自動実行します。再生中の直接操作は必須にしません。
- [演奏広場](/spec/hub/performance-plaza)では、ラジクジラが一人で演奏し、Playerが鑑賞できることを当面の完成条件とします。

「直進」「弧を描く」「旋回」等は検討例です。追従以外の具体的な動作や配布内容は、このページでは採用確定にしません。

## Playerから見た挙動

| 進行段階 | 行動 | Playerが行うこと |
|---|---|---|
| 最初のチュートリアル | 既定の追従パターンでPlayer周辺を漂い、移動に追従する | 行動設定を行わずに遊ぶ |
| 設定解放前 | 既定の追従パターンを使用する | 行動パターンを組み替えない |
| ストーリークリア後 | 行動設定機能が解放される | パターンの順番・継続小節数を設定する |
| 広場での演奏 | 設定済みの曲と行動をラジクジラが自動再生する | 事前設定と鑑賞で参加する |

設定解放は「新しい移動コードを初めて有効にすること」ではありません。初期から同じ行動パターンの仕組みで追従を実行し、進行に応じてPlayerが設定を編集できるようにします。

この解放条件はラジクジラの行動設定に対するものです。Mode／Conductの設定、ギルド、他の施設の解放条件へ転用しません。

## 初期追従パターン

追従パターンの位置関係、浮遊、急移動への追従、極端な距離差の補正は、[追従・浮遊](./follow-and-floating.md)を正本とします。

- Playerから直接操縦せず、自律的に追従します。
- シャオンダマ生成と並行して追従できます。
- 追従をPlayerのStateには含めません。
- 行動設定が未解放でも、初期追従は動作します。
- 初期追従のために、Playerが小節数を設定したり、曲ごとの編集を行ったりする必要はありません。

初期追従は曲の有無だけを理由に停止しません。曲に合わせた設定列を再生しているときは、その列の現在の行動パターンが移動を担当します。

追従コードと別パターンのコードが、同時に別々の目標位置でラジクジラを移動させないようにします。追加パターン実行中にも追従補正を重ねるかは、各パターンの詳細とともに決定します。

## 設定と再生に必要な情報

以下は受け渡す意味を定義したもので、実装上のフィールド名・型は固定しません。

| 情報 | 用途 |
|---|---|
| 行動設定を編集できるか | ストーリー進行に基づく設定解放の判定 |
| 対象の曲 | 演奏する曲と行動設定の対応 |
| 行動パターンの識別情報 | 実行する動作を特定する |
| パターンの並び順 | 曲中に実行する順序 |
| 各区間の継続小節数 | その行動を実行する音楽的な長さ |
| パターン固有の設定 | 具体的な動作の決定後に追加する値。内容は未決 |
| 現在の音楽位置・再生状態 | 区間の進行と開始・停止・終了の同期 |
| Playerや場面の基準情報 | 追従対象、演奏位置など、そのパターンが必要とする情報 |

設定内容と、現在どの区間を再生しているかという一時状態は分けます。演奏の終了や再開始だけで設定した並びを失わないようにします。保存タイミング、Save Dataの形式、設定の複数保存は未決です。

## 曲との同期

小節は固定の秒数として扱いません。BGM／音楽進行側が持つテンポ・拍子と音楽位置に合わせ、現在の行動区間と区間内の進行を決定します。

- ラジクジラ側が独自に曲の時間を進めたり、音声波形から小節位置を推測したりしません。
- 対象曲の開始位置を基準にし、曲と行動の開始が別々にずれないようにします。
- Pause等で曲の進行が止まる場合、曲に同期する行動区間の進行も止めます。
- 演奏終了後の通知や処理を、次の演奏へ持ち越しません。
- 曲のループ、曲長と設定列長の不一致、区間のつなぎ方は未決事項として扱います。

使用する音楽位置の考え方は[BGMとGameplayの接続](/spec/bgm/bgm-gameplay-connection)を参照します。ただし、広場演奏の開始・終了は[演奏広場](/spec/hub/performance-plaza)の別の実行単位で管理し、Battle開始条件を成立させるための処理は流用しません。

## 接続関係と責務

| 担当範囲 | 所有する判断・状態 | 次へ渡すもの |
|---|---|---|
| ゲーム進行・解放判定 | ストーリークリアの成立と、行動設定の解放可否 | 設定機能へ解放状態 |
| 行動設定 | 解放可否に従った編集、曲・順序・継続小節数等の設定 | 行動再生側へ設定済みデータ |
| BGM／音楽進行 | 曲の再生、テンポ・拍子に対応する音楽位置、再生状態 | 行動再生側へ音楽位置と開始・停止・終了 |
| 行動再生 | 現在のパターンと区間進行、ラジクジラの移動 | ラジクジラの世界内の位置・向き |
| BGM側の生成処理 | シャオンダマの生成対象・時刻・個数 | Spawn Systemへ生成要求 |
| ラジクジラの出現処理 | 現在の位置からシャオンダマを世界内へ出現させる | 出現した個体と完了状態 |
| シャオンダマ側 | 出現後の浮遊・寿命等 | 各利用場面に必要な状態 |
| 演奏広場 | 演奏の開始・終了と、その演奏で使う音・行動・演出の管理 | 各担当へ開始・終了、鑑賞用の表示 |

この表は接続する責務の区分です。各区分を独立したクラスにするか、どの既存コードへ割り当てるかは実装設計で決めます。

ラジクジラの移動とシャオンダマの生成内容は別の判断です。行動パターンの変更を理由に、BGM側が決定した音符・生成個数・生成時刻をラジクジラ側で再決定しません。出現処理の責務は[ラジクジラ｜シャオンダマ生成](./shaondama-spawning.md)を参照します。

また、ラジクジラの軌道だけで、出現後のシャオンダマが同じ軌道上へ並び続けるとは定めません。具体的な配り方・出現後の動きとの組み合わせは、後続の動作仕様で決めます。

## 当面の実装範囲と確認

最初は既定の追従パターンと、用意済みの曲を使って、ラジクジラの動き・音楽・シャオンダマの出現を接続できます。具体的な追加動作を決めるまで、この接続を保留する必要はありません。

確認する内容は次のとおりです。

- チュートリアルで行動設定を要求されず、Player周辺を追従する。
- 設定解放前は編集できず、ストーリークリア後に編集を解放できる。
- 設定解放の判定が移動コードや音楽再生側に重複して存在しない。
- 曲に同期する設定列を、設定済みデータと音楽位置から再生できる。
- シャオンダマ生成を始めても、現在の行動と移動の担当が二重にならない。
- 広場では演奏中のPlayer操作を必須にせず、自動演奏を鑑賞できる。

開発時に解放前・解放後の状態を検証する方法は実装設計に委ねます。検証用の解放状態を、製品での「ストーリークリア後」という条件に置き換えません。

戦闘で同じ行動設定を使用する構想は後続の検討対象とし、今回の広場演奏の完成条件には含めません。設定や音楽の共有は必須要件にしません。[既存のBattleプロトタイプ完成条件](/spec/game/prototype)にも広場・設定解放・ストーリー実装を追加しません。

## 未決事項

- 追従以外の行動パターン、配布するセットの内容と入手方法
- 各動作の距離・高さ・速度・曲線・姿勢・移動範囲
- 追加パターンの座標基準、Player追従補正、地形との干渉
- ストーリークリアを確定する具体的な条件と、その状態の保存方式
- 設定画面の位置・操作、設定列の上限、初期値、設定内容の保存形式
- 解放後の初期設定、未設定・不正な設定を受け取ったときの扱い
- 曲長と設定列長が異なる場合、区間の接続、ループ、曲途中からの再開
- シャオンダマの具体的な配り方と、出現後の動きとの組み合わせ
- 任意音源の取込方法、対応形式、テンポ・拍子等の入力方法
- 戦闘への設定適用時点と、広場・戦闘の環境差への対応

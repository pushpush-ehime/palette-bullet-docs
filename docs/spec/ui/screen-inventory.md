# 想定画面一覧・画面遷移

## このページの使い方

UI・画面設計を進めるため、想定する画面を22項目に整理します。**すべてを実装する決定ではありません。** 全画面、HUD、会話パネル、同じ画面のタブなど、Playerが見る情報と行う操作のまとまりを「画面」として登録しています。画面IDは資料を対応付けるためのもので、Scene名・クラス名・制作順を指定しません。

ラジクジラと拠点のコンセプト画は、今回の画面検討に使う参考絵として一旦完成扱いにします。画像中の比率からゲーム内寸法やUIの位置を確定しません。

画面の情報配置・見た目はUI・画面設計担当が進め、Gameplayの意味や遷移条件は各機能の正本に従います。個人の割当・進捗はチーム内の管理先で扱います。本ページの初版では、画面ラフ・最終デザイン・Runtime UIはいずれも未作成です。

各行の表示情報や操作は、既存仕様から画面化するための候補です。ボタン、数値欄、独立画面をすべて追加する指示ではなく、ラフで必要性とまとめ方を確認します。

## 対象範囲の読み方

| 対象範囲 | 意味 |
|---|---|
| プロトタイプ必須 | 既存の完成条件・接続仕様で必要な表示。仮UIでよい |
| プロトタイプ任意 | プロトタイプへ含めるか未決。必須の開始経路へ追加しない |
| 本編設計対象 | 確定した拠点機能・行動設定などを画面化する検討対象。独立画面の採用や全機能の実装時期は未決で、Battleプロトタイプには含めない |
| 完成版候補 | 将来の利便性やゲーム全体の構成から挙げた案。採用・仕様は未決 |
| 保留 | 元の機能の採否から未決。現時点でラフ作成を必須にしない |

## 画面遷移

### プロトタイプ

```text
起動
  ↓
Battle準備（UI-004の待機表示は任意）
  ↓
UI-001 Battle画面・HUD
  ↓ Gameが結果を確定
UI-002 共通Result
  ├─ Clear：操作lock → 解禁 → Continue → 拠点／Stage選択のroute
  └─ Game Over：操作lock → 解禁 → Retry → 新しいBattle準備 → UI-001

必須の準備／cleanupが失敗
  → UI-003 中断・再起動案内
  → アプリを終了し再起動（画面内Retryで復旧しない）

UI-005 Pause・UI-006 操作説明は、採用した場合だけ元画面に重ねる
```

**画面設計前に確認する点：プロトタイプでClear後のContinueが到着する具体的な受け先。** UI正本では拠点／Stage選択へのrouteですが、プロトタイプの完成条件はその実画面を対象外としています。Game側と仮の受け先を具体化する必要があります。本一覧では拠点画面を新たに必須化せず、ClearにRetryを追加して解決することもしません。

### 本編・拠点の構成案

以下の線は導線の検討案です。施設の入口や、画面を開く順番の実装確定を意味しません。

```text
ゲーム開始（UI-201の採用・本編開始地点は未決）
  ↓
UI-101 拠点の探索画面
  ├─ UI-102 NPC・受付との会話
  │    └─ UI-103 クエスト一覧・詳細・受注
  ├─ 掲示板 → UI-103 クエスト一覧・詳細・受注
  │                 └─ UI-104 Stage選択・出発準備 → Battle準備 → UI-001
  ├─ 調律工房 → UI-105 Mode構成／UI-106 Conduct設定
  ├─ UI-107 試走スペース
  ├─ UI-108 レコード販売所
  └─ 演奏広場 → UI-109 演奏準備 → UI-110 自動演奏・鑑賞
                                    └─ 終了 → 準備状態へ

UI-111 行動パターン設定
  └─ ストーリークリア後に編集解放
     入口の施設・メニュー、UI-109と統合するかは未決

本編BattleのResult：
  Clear → Continue → 拠点／Stage選択
  Game Over → Retry → 現在Stageの新しいBattle準備
```

会話・施設メニューを閉じた場合の基本案は呼出元へ戻ることです。操作中の未保存変更、購入や出発などの確定操作、演奏中の終了については、各画面の仕様で戻り方を確定します。

## 画面ではなく共通部品として検討するもの

- ボタンの通常・Hover・Focus・押下・使用不可の表示。
- タブ、一覧と詳細、説明文、操作キーの案内。
- 内容確認・変更取消等の確認ダイアログ。どの操作に確認が必要かは各画面で決める。
- 通知・簡潔なフィードバック。専用の全画面へ遷移するかは内容に応じて判断する。
- データなし、未解放、準備中、読込失敗等の状態表示。

これらを一律に独立画面として数えません。通常の「操作できない」表示を、UI-003のシステム中断として扱うこともしません。

## 画面を描く順番の提案

1. **UI-001 Battle画面・HUD**：通常状態の1枚から始め、照準・シャオンダマ・敵とHUDが重ならないか確認する。次にCharge中などの状態差分を描く。
2. **UI-002 共通Result、UI-003 中断案内**：正常終了と異常時の出口をそろえる。Resultの状態別詳細はPB-TASK-0022へつなぐ。
3. **UI-101～104 拠点・会話・クエスト・出発**：町で依頼を知ってBattleへ行く導線を一続きで描く。
4. **UI-109～111 演奏準備・鑑賞・行動設定**：単独自動演奏に必要な操作と、クリア後に解放する編集を区別して描く。
5. **UI-105～108 工房・試走・販売所**：機能仕様を確認しながら情報配置を描く。
6. 任意画面・完成版候補は、採用と必要性を確認したものから追加する。

これはラフ制作の順番の提案であり、各機能の実装順・期限・担当者の割当ではありません。プロトタイプのMode／Conduct表示は、通常のCharge→発射→浄化の接続確認後に追加する完成方針に合わせます。

## 画面ラフの記録テンプレート

最初はプロトタイプの基準である**1920×1080、キーボード・マウス**で情報の位置と大きさを確認します。仮色・仮アイコン・仮文言を使い、状態差分は同じ画面IDへまとめます。本編の最終対応解像度をこれだけで固定しません。

画面を描いたら、対応する個別UIページに以下を記録し、本一覧からリンクします。画像や制作ツールのURLが未登録の間は「未作成」のままにし、存在しない画像リンクを置きません。

```markdown
## 画面ラフ

- 画面ID・名称：
- 対象範囲：
- この画面で判断・実行できること：
- 参照する機能仕様：
- 初稿画像・編集元：未作成
- 入口／開く条件：
- 主な表示情報：
- 主な操作と操作後の行き先：
- 閉じる／戻る操作と未保存変更の扱い：
- 状態差分：通常／情報なし／未解放／待機／使用不可等、該当するもの
- Gameplay入力との切替・同時操作の扱い：
- 確定したこと：
- 未決事項と確認先：
```

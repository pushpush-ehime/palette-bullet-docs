# バトルHUD

## 設計の位置づけ

[想定画面一覧](./screen-inventory.md)の **UI-001 Battle画面・HUD** を具体化するページです。2026年9月13日までの企画相談で決まった、**通常Battleのプレイ中に必要な情報と、プロトタイプで採用する配置・表現**を画像付きで記録します。最終的なゲームUIらしい装飾、質感、アイコン、アニメーションは今後詰めます。

基準は1920×1080・キーボード／マウスです。PlayerとEnemyを見ながら遊ぶことを前提に、視界の端でも必要な音や装填状態が読み取れることを重視します。照準周辺とシャオンダマを選ぶための視野を確保します。

シャオンダマ自体は世界内のオブジェクトであり、HUDの制作物には含めません。一方、AttackEventに要求される音や装填状況を伝える**音枠はHUD**です。今回は通常プレイ中に絞り、Pause・Result・中断案内の詳細設計は対象外とします。

## 採用するHUDと配置

| HUD | 必要な情報・役割 | 採用する配置 | 機能の正本 |
|---|---|---|---|
| HP・Stamina | 生存状態と行動の余裕。不足時の表現は今後検討する | **左下** | [Playerステータス](/spec/player/player-status) |
| レティクル | 狙う方向・位置の手がかり。世界内の対象を示すMarkerとは分けて考える | 照準位置を示す画面中央付近 | [照準](/spec/camera/aim)、[Marker](/spec/combat/marker) |
| AttackEvent予告 | 必要な音、装填状況、発射までの時間、コード／アルペジオの違い | **画面上部に横長の帯。縦幅は小さく、発射ポイントは一番左** | [AttackEvent](/spec/bgm/bgm-attack-event)、[Allocation](/spec/draw-system/charge-allocation)、[音楽とGameplayの接続](/spec/bgm/bgm-gameplay-connection) |
| Mode | 現在のModeと切替先。現在・適用待ち・使用不可の見せ分けは今後検討する | **画面右側に1・2・3・4を縦に並べる** | [Mode／Conduct](/spec/player/player-action-mode-change-and-conduct) |
| Conduct | ホイールで選ぶConductと現在の選択 | **右下に、上1個・下2個の三角形配置** | [Mode／Conduct](/spec/player/player-action-mode-change-and-conduct) |
| 操作ガイド | 今できる操作と、そのキー・マウス入力 | 採用する。ラフの下中央配置は仮 | [入力と操作](/spec/player/input-and-controls) |

これらをプレイ中に必要なHUDとして扱います。ただし、すべての補足情報を常時表示する決定ではありません。AttackEvent予告は**予告開始時に必ず表示**します。HP・Staminaの数値併記、各部品の寸法、細かい形は未決です。

## AttackEvent予告に表示する情報

| 読み取りたいこと | 表示する情報 |
|---|---|
| 何を、いくつ装填すればよいか | 要求される音の種類・数。C・D・Eなどの音名と♯・♭を表示する |
| どこまで準備できたか | 音ごとの空／装填済み。同じ音枠の状態差で、準備できた音と不足音を伝える |
| 今どのAttackEventに装填するか | 現在の装填対象のまとまりだけ、外枠を強調する |
| いつ発射されるか | 左端の発射ポイントまでの距離。アルペジオは各音の間隔も使う |
| どのように発射されるか | コード／アルペジオを音枠の並べ方で見分ける |

### 音枠と装填状態

**要求される音1個につき、1つのスロット（音枠）**を用意します。同じ音が複数必要な場合も、必要な個数だけ別の枠で表します。

- **音名**：C・D・Eなどの絶対的な音名と、必要な♯・♭を表示します。色を付けても文字は残します。
- **空の状態**：音名と色付きの輪郭が見え、装填先の空き枠だと分かる表現にします。
- **装填済み**：対応する色で面を埋め、空の状態との違いを大きくします。
- **視認性**：文字を読み続けなくても、色・輪郭・塗り面積から不足が分かることを目指します。暗い空枠が背景に埋もれないようにします。

「要求される音」と「準備できた音／まだ足りない音」は、別々の一覧を増やさず、同じ音枠で伝えるプロトタイプ方針です。チェックマーク、点滅、装填時のアニメーションなどは未決です。

音名の絶対表記と、既存の色定義は分けて扱います。[シャオンダマのデータ仕様](/spec/shaondama-music/orb-data)ではNormalの色はKeyに対する度数に対応する7色です。HUDと世界内の色をどう対応させるかは、この定義と整合させます。**画像中の色を、C♯などの絶対音高に対する固定配色として確定しません。**

### コード／アルペジオの形

| 種類 | プロトタイプでの表現 | 伝える意味 |
|---|---|---|
| コード（Chord） | 要求される音枠を**縦に積む** | 同じ発射タイミングの音のまとまり |
| アルペジオ（Arpeggio） | 音枠を**横に並べる** | 順番に発射する音のまとまり。横の間隔を実際の発射間隔に合わせる |

文字ラベルだけに頼らず、まとまりの形でも種類を伝えます。アルペジオの並び順は音楽上の発射順であり、Playerが装填しなければならない入力順を追加するものではありません。

[![音枠の初期比較図。空枠と塗りつぶした装填済み枠、コードの縦並びとアルペジオの横並びを比較する。](/images/battle-hud/note-slots-2026-09-13.png)](/images/battle-hud/note-slots-2026-09-13.png)

*音枠の状態と並べ方を相談した初期比較図です。この図の等間隔の横並びや説明は形の比較用であり、最終的な時間表現を示しません。その後、アルペジオの横間隔は発射間隔に合わせ、AttackEvent全体を外枠で囲む方針に決まりました。配置・まとまりは上のHUD配置ラフ、時間の扱いは以下の本文を参照してください。*

### AttackEventのまとまりと現在の装填対象

各AttackEventは、音枠全体を囲む外枠でひとまとまりとして表します。そのうち、**今装填するAttackEventだけ、まとまり全体の外枠を目立たせます**。音を識別する色と、装填対象を示す強調は区別できるようにします。

対象は[Allocation](/spec/draw-system/charge-allocation)のCurrentを参照します。HUDが見た目の位置から独自に対象を選びません。Currentが変わったら強調も移り、Currentがなければ対象の強調を出しません。装填完了などで発射前にCurrentが移る場合も、予告の残り時間と対象の強調を別に扱います。

### 出現・移動・表示終了

| タイミング | HUDの動き |
|---|---|
| **予告開始** | 対象AttackEventの予告／Charge受付開始と同時に、右側に現れる |
| **発射まで** | 左へ流れ、要求される音・準備状況・コード／アルペジオの違いを表示する |
| **AttackEventの発射タイミング（Fire）** | 一番左の発射ポイントに到達し、**そのAttackEvent全体のCharge受付が終了**する。コードはまとまりの表示を終了する |
| **アルペジオの後続音** | 受付は終了したまま、各音をそれぞれの発射タイミングまで表示する。各音が発射ポイントに到達したら、その音の表示を終了する |

発射ポイントはActual BGMの `Fire Music Position` に対応します。表示が先に到達したことや描画frameの丸めを、Gameplayの締切にしません。Pause中は音楽時間と一緒に進行を止め、Resume後も同じoccurrenceの残り時間を表します。予告時刻と移動の時間対応は[AttackEvent](/spec/bgm/bgm-attack-event)を正とします。

アルペジオは**各音の横間隔を発射間隔に合わせ、各音の発射に合わせて順次消す**方針です。先に発射した音が消えても、残りの音を詰めて並べ直さず、発射までの時間関係を維持します。最後の音の表示終了で、そのまとまりの表示も終えます。

アルペジオでも、後続Entryの発音・発射までCharge受付を延ばしません。Fire後に残る音は発射待ちの表示であり、追加装填できる枠と誤認させないようにします。現在の装填対象の強調は、その時点のCurrentに従います。

空のまま残った音枠も、その音の予定時刻で表示を終了する扱いを基本とします。ただし、**表示の消去自体は発射成功の通知ではありません**。実際の発射・発音はGameplayの割り当て状態と判定を参照します。未装填時の補足フィードバック、フェードや発射時の演出は未決です。

### 予告の重なりへの対応は後で検討する

基本は太鼓の達人のように、同じ時間軸の上を右から左に流れる見せ方です。**重ならないための具体策は、現時点では決めません。**

先に曲側と、どのコードやフレーズをどの程度AttackEventにするか相談します。実際の曲データで予告の重なりや読みづらさが問題になった段階で、対応を検討します。レーン分け、表示数上限、位置の補正、曲側への密度制限などを、このラフから新たな必須条件として追加しません。重なり対策の確定を、現在のHUD制作の前提にする必要はありません。

## Mode・Conduct・操作ガイド

### Mode

原神の切替表示のような配置イメージで、**画面右側に1・2・3・4を縦に並べます**。対応する切替入力が分かる表示にします。

現在のMode、次の小節頭で適用される切替待ち、切替できない期間の具体的な表現は今後決めます。切替入力の直後から、すでに適用済みだと誤認させないようにします。切替のタイミング自体は[Mode／Conduct](/spec/player/player-action-mode-change-and-conduct)を正とします。

### Conduct

**画面右下に、上1個・下2個の三角形で選択肢を並べ、マウスホイールで循環選択**します。横一列のボタン配置ではなく、会話で提示された3点の循環図を配置の基準にします。選択中の枠を強調します。

ラフでは「未選択・ひろがり・やまびこ」の3枠を仮表示しています。これは既存仕様の選択肢を使った例であり、3種類目のConduct効果を新規追加する決定ではありません。アイコン、各選択肢を置く頂点、循環を示す矢印の描き方は未決です。

ここで示す選択は、次のChargeに使うものです。選択を変えたことが、進行中Chargeのスナップショットや付与済みの内容まで変更したように見えない表現にします。使用不可・クールダウンの見せ方は、[Mode／Conduct](/spec/player/player-action-mode-change-and-conduct)と合わせて詳細化します。

### 操作ガイド

**今できる操作と、対応するキー・マウス入力**を必要な場面で表示します。会話での参考イメージは、無双シリーズやモンスターハンターのアクション中の操作案内です。

すべての操作を常に一覧表示する方針ではありません。ラフの下中央の位置や「左クリック：Charge」「Shift：回避」などの文言は仮置きです。案内する操作、表示条件、使用不可の示し方、最終配置は[入力と操作](/spec/player/input-and-controls)を参照して今後決めます。

## Gameplayとの接続と状態差分

Charge成功はAttackEvent occurrenceへの割り当て・Reserved化であり、その場での発射ではありません。Palette Bullet化・発射は対応するAttackEventの発火処理によります。HUDの表示もこの違いを保ちます。[Charge](/spec/player/player-action-charge)、[Allocation](/spec/draw-system/charge-allocation)、[入力と操作](/spec/player/input-and-controls)を正本とし、独立した発射ボタンやGameplay判定を追加しません。

画面上の情報から、勝敗・Charge成功・発火・Mode適用をUIが独自に判定する構成にはしません。後続の詳細設計では、通常時に加えて次の状態を比較します。

- 照準対象がないとき、装填先のCurrentがないとき。
- 音枠が空／一部装填済み／すべて装填済みのとき。Charge中・成功・不成立の違い。
- アルペジオの受付が終了し、後続音の発射だけを待っているとき。
- HP・Staminaが少ないときや、必要な操作ができないとき。
- Modeの現在・適用待ち・使用不可、Conductの次回選択・使用不可の違い。

これらをすべて専用ゲージや別画面にする決定ではありません。[プロトタイプの完成方針](/spec/game/prototype#completion-policy)に沿って段階的に確認します。制作順・成果物・完了条件は[PB-TASK-0048](/tasks/ui/pb-task-0048#rough-order)を参照します。

## 未決事項

- **予告帯の具体的な高さ、文字サイズ、余白、HP・Staminaの数値表示**。確認先：UI設計・Camera・企画。詳細ラフと実機で、戦闘を見る視野を確保できるか確認する。
- **Modeの現在・適用待ち・使用不可、Conductの次回選択と進行中Chargeの区別**。確認先：UI設計・Player担当。Mode／Conductの詳細設計前に決める。
- **操作ガイドの操作一覧、表示条件、使用不可の示し方、最終配置**。確認先：UI設計・入力担当。操作仕様と照合して詳細化する。
- **♯・♭や異名同音の表記ルール、Keyに対する色とHUDの音名の対応**。確認先：UI設計・BGM／シャオンダマ担当。既存の音・色の定義と整合させて決める。
- **対象なし、Charge不成立、HP・Stamina不足、未装填で発射時刻を迎えた場合の補足表現**。確認先：UI設計・各機能担当。状態差分の詳細ラフで比較する。
- **ゲームUIとしての配色・文言・アイコン・音・アニメーション**。確認先：UI設計・デザイナー・サウンド担当。プロトタイプ方針を基に詳細化する。
- **複数予告が重なる場合の対策は後回しにする**。先に曲側とAttackEventにするコード・フレーズや量を相談し、実際に問題が出た段階でUI設計と検討する。現在のHUD制作を止める条件にはしない。

未決事項と継続可能な範囲は[画面一覧のQ-02](/spec/ui/screen-inventory#open-questions)、画像・編集元・レビュー結果の記録方法は[PB-TASK-0048](/tasks/ui/pb-task-0048#rough-record)へつなぎます。
